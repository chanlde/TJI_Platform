## 状态

- 状态：active
- 更新时间：2026-08-11
- 用途：Project 08 目标设备、MCU、服务端与产品联合验收

## 使用说明

- 本表只记录 Project 08 的外部设备、MCU、服务端和产品确认，不替代自动测试。
- 每次只勾选有可追溯证据的项目；失败项必须保留日志并恢复到可用版本后才能继续。
- 不要求增加额外加密：固件按现有 SHA256/回滚能力验收，Bootloader 尚未建立签名能力时记录风险，不伪造客户端单端验签。

## 2. App 更新

- [ ] 正式服务器返回 TJI Platform 独立记录，包名、版本、大小、SHA256、signer 和 HTTPS 地址与发布 manifest 一致。
- [ ] 从当前正式版点击更新，下载完成后系统安装器显示正确 App 名称，覆盖安装成功且数据保留。
- [ ] 下载时断网，App 不产生安装入口；恢复网络后重新操作能够成功。
- [ ] 使用损坏、截短、错包名或错 signer 的测试候选时，客户端拒绝且当前版本仍可使用。
- [ ] 用户取消系统安装或拒绝“安装未知应用”权限后，当前业务不受影响；授权后再次点击可以继续。
- [ ] 下载或安装阶段重启设备后，旧版本仍能正常启动、登录和控制；重新发起更新能够成功。
- [ ] 停用测试更新记录后，客户端不再提示该版本。
- [ ] 使用上一稳定源码、同一 Release Key 和更高 `versionCode` 构建的应急恢复版完成覆盖安装与业务验证。

## 3. MCU 固件 OTA（每个启用产品分别复制一份）

- [ ] MCU 负责人确认量产 Bootloader commit、SHA256 校验位置、待确认启动条件和回滚条件。
- [ ] App 页面展示的当前版本、目标版本和升级说明正确。
- [ ] 正常 OTA 成功，设备重启后报告目标版本，原有状态读取和控制命令正常。
- [ ] 下载中断或 Broker/网络断开后不会启动不完整镜像；恢复后的行为符合 MCU 约定。
- [ ] 篡改一个字节或提供错误 SHA256 时设备拒绝镜像，旧固件仍能启动。
- [ ] OTA 中途重启后设备能进入旧固件或继续既定恢复流程，无永久离线。
- [ ] 在 MCU 负责人指定的安全阶段执行一次断电，Bootloader 回滚成功且设备重新上线。
- [ ] 低于最低电量时 App 拒绝启动；设备未上报电量时按当前兼容策略记录实际行为。
- [ ] 可用空间字段落地后验证空间不足；字段未落地前由 MCU 证明下载/写入失败不会破坏旧镜像。
- [ ] OTA 成功、失败、回滚后再次升级不被旧 reservation 阻塞。
