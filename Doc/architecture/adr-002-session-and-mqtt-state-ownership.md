# ADR-002：会话状态与 MQTT 真值归属

## 状态

- 状态：active
- 决策状态：已采纳
- 日期：2026-07-26

## 背景

登录设备、当前选择、产品运行时和 MQTT 订阅曾分别保存在多个 ViewModel/全局变量中。界面切换或账号切换时，这些副本可能不同步；MQTT 代码还可能在 SUBACK、UNSUBACK 或 PUBACK 到达前提前报告成功。

## 决策

1. `AppSessionStore` 是账号、绑定设备和当前设备选择的唯一会话来源。产品 Repository 只保存设备实时状态，不复制账号会话。
2. `ProductModuleRegistry` 和 `ProductRuntimeRegistry` 每种产品只允许注册一个实现；重复注册在启动阶段失败，不再静默覆盖。
3. `MqttSubscriptionManager` 保存“Broker 已确认”的实际订阅集合。订阅、取消订阅和挂起式发布必须等待对应回执；账号切换用 generation 使晚到结果失效。
4. 同一设备的入站消息进入一个有界顺序队列。过载时丢弃最旧消息、保留最新状态，避免无限堆积。
5. MQTT 连接属于账号/进程会话，不属于 Activity。Activity 重建不得主动断开；登出或服务销毁负责清理。

## 影响

- 页面不再维护重复设备选择状态，账号切换的清理路径更明确。
- 调用方收到“发送/订阅成功”时，含义是 Broker 已确认，而不是仅完成本地方法调用。
- 注册配置错误更早暴露；高频入站在极端过载时优先保证最新状态与内存上限。
- 保持手工容器和按产品模块组织，不为本次整理引入 Hilt、UseCase 层或大量小接口。

## 未采用方案

- 每个页面各自保存会话副本：同步成本高，容易产生陈旧状态。
- 无界消息队列：能保留全部历史，但设备异常突发时可能耗尽内存。
- 按命令、解析器、状态字段继续拆成大量小文件：增加跳转成本，且没有形成独立生命周期或复用边界。
