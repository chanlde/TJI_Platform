# ADR-003：独立喊话 UDP Relay 使用部署期共享凭证

- 状态：已采纳
- 日期：2026-08-01

## 背景

喊话链路只有 Android App、MCU 和公网 UDP relay，没有可签发短期凭证的业务后台。
relay 必须阻止任意公网来源按设备编号注入音频，但生产凭证也不能提交到 Git 或输出到日志。
此前 relay 已配置凭证，而 Android 构建未注入同一值，导致 TTS 合成和 Opus 编码成功后在传输前失败。

## 决策

1. App、MCU 和 UDP relay 使用同一份随机部署凭证；源码不提供生产默认值。
2. Android 构建按 Gradle 属性、环境变量、`local.properties` 的顺序读取凭证。
3. 测试机安装脚本通过 SSH 从正在运行的 relay 进程读取现有凭证，仅在子进程环境中注入 Gradle；不打印、不落盘。
4. 缺少凭证不得导致页面闪退；只有使用 relay 的功能失败，并显示“语音传输服务未配置”或“设备麦克风监听服务未配置”。
5. 凭证轮换必须同步更新 relay、MCU 和 App，不允许只改其中一端。

## 影响

### 正面

- 不引入不存在的认证后台或额外服务。
- 保留公网 UDP 的最低访问控制。
- 测试构建不再依赖人工复制密钥，降低漏配概率。
- 密钥不会进入版本库、构建日志或本地属性文件。

### 负面

- 凭证仍会存在于最终 APK 中，具备逆向能力的人可以提取；它不是用户级授权机制。
- 任一端轮换不一致都会中断语音链路。
- 安装脚本需要对 relay 主机具有只读进程配置权限的 SSH 凭据。

## 备选方案

- **取消 relay 鉴权**：部署最简单，但任何公网来源都可尝试注入音频，不接受。
- **业务后台签发短期凭证**：安全性更高，但当前系统没有该后台，属于不必要的新增运行组件。
- **把生产凭证写入源码**：能工作，但会进入 Git 历史和所有构建，不接受。

## 失败模式与处置

- relay 未运行或 SSH 不可达：安装脚本在构建前失败，不生成错误配置的 APK。
- relay 凭证为空或含空白：安装脚本拒绝继续。
- App 缺少凭证：页面仍可打开，本机试听可用，设备语音传输给出明确错误。
- 三端凭证不一致：检查 relay 日志中的注册拒绝，并同步轮换三端配置。
